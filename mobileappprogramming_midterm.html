01개발환경 준비하기

한 줄 요약안드로이드 스튜디오로 프로젝트를 만들고, 에뮬레이터나 폰에서 실행하고, 다 만들면 AAB 파일로 Play 스토어에 올린다.

프로젝트 만들 때 고르는 것

  • Empty Views Activity = 우리가 쓰는 방식 (XML로 화면 만들기) / Empty Activity = 컴포즈 방식
  • Package name = 앱의 이름표. 예) com.knu.myfirstapp – 세상에 하나뿐이어야 함
  • Minimum SDK = API 24로 정하면 → API 23(안드로이드 6) 폰에는 설치 자체가 안 됨
  • 빌드 설정 언어는 build.gradle.kts(Kotlin DSL) 권장
  • Logcat = 앱이 남기는 로그를 보는 창. 예) 코드에 Log.d("kkang", "클릭") → Logcat에 “클릭”이 찍힘

앱 실행하기

  • 컴퓨터 안의 가짜 폰 = AVD(에뮬레이터). Device Manager에서 만든다
  • 윈도우 10/11은 에뮬레이터 가속에 WHPX 권장 (AEHD는 2026.12.31 지원 종료)
  • 내비게이션 버튼 3개: ◁ Back(뒤로) · ○ Home(홈) · ▢ Overview(최근 앱)

앱 출시하기

도장(서명 키)을 잃어버리면 “내가 만든 앱”이라는 걸 증명할 수 없어서 업데이트를 영원히 못 해요. 그래서 진짜 도장(앱 서명 키)은 구글이 금고에 보관하고, 개발자는 “택배 보낼 때만 쓰는 도장”(업로드 키)을 써요. 업로드 키를 잃어버리면? 새로 만들어서 구글에 등록하면 끝.

02안드로이드 앱의 기본 구조

한 줄 요약앱은 4가지 컴포넌트로 이루어지고, 매니페스트에 등록해야 시스템이 알아본다. 문자열·이미지 같은 값은 res 폴더(리소스)에 따로 둔다.

안드로이드 특징

  • 리눅스 기반의 공개 운영체제, 자바나 코틀린으로 개발
  • 삼성, 구글 등 여러 회사가 폰을 만들 수 있고, Play 스토어 말고도 배포 가능
  • 모든 앱이 평등: 기본 문자 앱이든 내가 만든 문자 앱이든 똑같은 API를 씀 → 기본 앱을 내 앱으로 바꿔 쓸 수 있음

컴포넌트 = 앱의 부품

일반 클래스: val user = User() 처럼 내가 객체를 만들고 버림.

컴포넌트 클래스: MainActivity()를 내가 직접 만들지 않아요. 사용자가 아이콘을 누르면 시스템이 객체를 만들고, 앱을 닫으면 시스템이 없애요. → 생명주기를 시스템이 관리하면 컴포넌트 클래스.

컴포넌트하는 일실제 예상속 클래스매니페스트
액티비티화면채팅 목록 화면, 채팅방 화면Activity<activity>
서비스백그라운드 작업앱을 닫아도 계속 나오는 음악Service<service>
콘텐츠 프로바이더데이터 공유연락처 앱이 다른 앱에 연락처 제공ContentProvider<provider>
브로드캐스트 리시버시스템 이벤트 수신“배터리 부족”, “부팅 완료” 알림 받기BroadcastReceiver<receiver>

4가지 중 무엇인지는 상속받은 상위 클래스를 보고 구분해요. class MyService : Service()면 서비스.

컴포넌트는 독립된 실행 단위

애플리케이션 라이브러리: 메신저 앱에서 [카메라] 버튼을 누르면 내 앱이 카메라를 직접 만들지 않고 카메라 앱의 화면을 빌려 씀 → 다른 앱을 라이브러리처럼 사용.

리소스

코드에 textView.text = "안녕하세요"라고 직접 쓰면, 영어 버전을 만들 때 코드를 다 고쳐야 해요. 대신 res/values/strings.xml에 넣어 두면 파일만 바꾸면 됩니다.

<!-- res/values/strings.xml -->
<string name="mytxt">동해 물과 백두산이 마르고 닳도록</string>

// 코드에서 사용
textView.text = resources.getString(R.string.mytxt)

리소스 = 코드에서 정적인 값을 분리한 것. 이미지 등 몇몇 빼고 대부분 XML로 작성.

프로젝트 폴더 구성

  • res/layout/test.xml 추가 → 코드에서 R.layout.test / res/drawable/send.png → R.drawable.send
  • 리소스 ID(int)는 바이트코드(R.jar)로 자동 생성 (과거엔 R.java)
  • mipmap = 앱 아이콘 / drawable = 일반 이미지
파일명 규칙 예시 addUser.xml ✘ (대문자) → add_user.xml ✔ · 1user.png ✘ (숫자 시작) · res/drawable/icons/a.png ✘ (하위 폴더) · res/images/ ✘ (정해진 폴더명 아님)

build.gradle.kts (모듈 수준)

그래들 = 빌드 도구. 프로젝트 수준·모듈 수준 두 파일 중 대부분은 모듈 수준에 작성 (모듈 = 앱 하나).

plugins { alias(libs.plugins.android.application) }   // 이 모듈은 "앱"이다
compileSdk { version = release(37) }   // API 37로 컴파일
applicationId = "com.example.androidlab"   // 앱 식별자 (Play 스토어 주소에도 쓰임)
minSdk = 24        // API 24 미만 폰엔 설치 불가
targetSdk = 37     // API 37 기준으로 개발
versionCode = 1    // 업데이트할 때마다 2, 3 … 증가 (숫자)
versionName = "1.0"   // 사용자에게 보이는 버전 (문자열)
compileOptions { sourceCompatibility = JavaVersion.VERSION_11; targetCompatibility = JavaVersion.VERSION_11 }
kotlinOptions { jvmTarget = "11" }
dependencies {
    implementation(libs.androidx.appcompat)          // SDK에 없는 라이브러리는
    implementation(libs.androidx.constraintlayout)   // 전부 여기에 선언
}

targetSdk의 SDK는 기본 적용, androidx나 오픈소스 라이브러리는 dependencies에 선언해야 함.

AndroidManifest.xml

<manifest xmlns:android="http://schemas.android.com/apk/res/android">   <!-- 루트 태그, 표준 네임스페이스 -->
  <application
      android:icon="@mipmap/ic_launcher"      <!-- res/mipmap/ic_launcher.png = 앱 아이콘 -->
      android:label="@string/app_name"       <!-- strings.xml의 app_name = 앱 이름 -->
      android:theme="@style/Theme.AndroidLab"> <!-- 테마 -->
    <activity android:name=".MainActivity" android:exported="true">
      <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
      </intent-filter>
    </activity>
  </application>
</manifest>
  • 컴포넌트는 매니페스트에 등록해야 시스템이 인지. 예) DetailActivity를 만들고 등록을 안 하면 실행 시 오류
  • <activity>의 name 속성은 필수. .MainActivity의 점(.) = 앱 패키지 경로 안에 있다는 뜻
  • @로 시작 = 리소스 참조
  • MAIN + LAUNCHER = “홈 화면 아이콘을 누르면 이 액티비티가 열린다”. intent-filter를 지우면 설치는 되지만 아이콘이 안 보여서 사용자가 실행할 수 없음

03코틀린 시작하기

한 줄 요약변수는 val(못 바꿈)/var(바꿈), 함수는 fun, 반복은 for (i in 1..10). 실행 결과 문제가 가장 많이 나오는 장.

코틀린이란

젯브레인스가 만들고 2017년 구글이 안드로이드 공식 언어로 지정. JVM 기반이라 자바와 100% 호환, 널 안전성 지원, 코루틴으로 비동기 처리가 쉬움.

변수: val vs var

val = 주민등록번호처럼 한 번 정하면 안 바뀌는 값 · var = 나이처럼 계속 바뀌는 값

val birth = 20050301   // val = 못 바꿈
var age = 21           // var = 바꿀 수 있음
age = 22                // OK
// birth = 20050302     // 오류! Val cannot be reassigned
val score: Int = 90    // 타입은 이름 뒤 콜론. 생략하면 90을 보고 Int로 추측(타입 추론)
val data1: Int         // 오류! 최상위 변수는 바로 초기화해야 함
class User { val data2: Int }   // 오류! 클래스 멤버도 마찬가지
fun f() {
    val data3: Int     // OK. 함수 안은 나중에 넣어도 됨
    data3 = 10
}

초기화 미루기: lateinit, by lazy

lateinitby lazy
뜻“값은 나중에 직접 넣을게요”“처음 쓰는 순간 이 블록을 실행해서 넣어 주세요”
키워드var만 가능val에 사용
타입 제한Int, Long, Short, Double, Float, Boolean, Byte 불가없음

}
in main...... in lazy...... 20 20

데이터 타입

  • 코틀린의 모든 변수는 객체 → val a: Int = 10; a.plus(5) 처럼 함수 호출 가능
  • 문자열 템플릿: val name = "kim"; println("이름: $name, 내년 나이: ${age + 1}") → 이름: kim, 내년 나이: 23
  • 삼중 따옴표 """ = 줄바꿈·들여쓰기를 그대로 저장
타입뜻예시
Any모든 타입의 조상val a: Any = 10; val b: Any = "hi"; val c: Any = User() 모두 OK
Unit반환값 없음fun some(): Unit { println(10) } = fun some() { ... }
Nothing의미 있는 값 없음fun fail(): Nothing { throw Exception() } / Nothing? 에는 null만

함수

fun price(count: Int, unit: Int = 1000): Int {   // unit 기본값 1000원
    // count = 5   // 오류! 매개변수는 자동 val
    return count * unit
}
println(price(3))                    // 3000  (unit = 1000 자동)
println(price(3, 500))               // 1500
println(price(unit = 200, count = 2))// 400   (이름으로 주면 순서 상관없음)

fun check(data: Any) {
    when (data) {
        is String -> println("문자열")    // is: 타입이 String이면

04코틀린 객체지향 프로그래밍

한 줄 요약생성자는 주 생성자(1개, 클래스 이름 옆)와 보조 생성자(여러 개, 본문 안). 상속하려면 open, 재정의하려면 override.

클래스와 객체

class User {
    var name = "kkang"                      // 변수
    constructor(name: String) { this.name = name }   // 생성자
    fun someFun() { println("name : $name") }      // 함수
    class SomeClass { }                      // 클래스
}
val user = User("kim")   // new 없이 생성
user.someFun()            // name : kim

주 생성자 vs 보조 생성자

주 생성자보조 생성자
위치클래스 이름 옆 class User(name: String)클래스 본문 안 constructor(...) { }
개수최대 1개 (필수 아님)여러 개
constructor생략 가능생략 불가
본문 코드init { } 블록자기 { }

상속

부모 클래스 Animal(이름, 먹기)을 만들어 두면, 자식 Dog는 이름·먹기를 다시 안 만들고 물려받아요. 단, 코틀린은 기본이 “상속 금지”라서 부모에 open을 붙여야 해요.

open class Animal(name: String)              // open 없으면 상속 불가
class Dog(name: String) : Animal(name)      // 콜론 + 부모 생성자 호출

open class Super { constructor(name: String) { } }
class Sub : Super {                          // 주 생성자가 없으면
    constructor(name: String) : super(name) { }   // 보조 생성자에서 super()
}
// class Sub1(name: String) : Super() { }  // 오류! Super엔 인자 없는 생성자가 없음

오버라이딩

open class Super {
    open var someData = 10
    open fun someFun() { println("i am super class function : $someData") }
}
class Sub : Super() {
    override var someData = 20
    override fun someFun() { println("i am sub class function : $someData") }
}
fun main() {
    val obj = Sub()
    obj.someFun()
}
i am sub class function : 20

override한 멤버는 그 자체로 open → 손자 클래스가 또 override 가능. 오버라이딩 안 하고 물려받기만 하면 obj.superData = 20; obj.superFun() 처럼 내 것처럼 사용.

05코틀린의 유용한 기법

한 줄 요약람다 = 이름 없는 함수 { 매개변수 -> 본문 }. 널 안전성 연산자 ?. ?: !! 의 차이를 확실히.

람다 함수

fun sum(no1: Int, no2: Int): Int { return no1 + no2 }   // 일반 함수
val sum2 = { no1: Int, no2: Int -> no1 + no2 }           // 같은 일을 하는 람다
println(sum2(10, 20))   // 30
상황쓰는 법
매개변수 없음{ -> println("function call") } 또는 { println("function call") }
매개변수 1개val some: (Int) -> Unit = { println(it) } → some(10) 출력 10
return{ a: Int, b: Int -> return a * b } ✘ 오류
val some = { no1: Int, no2: Int ->
    println("in lambda function")
    no1 * no2           // ← 마지막 줄이 반환값
}
println("result : ${some(10, 20)}")

고차 함수

고차 함수 = 함수를 매개변수로 받거나 함수를 반환하는 함수.

fun hofFun(arg: (Int) -> Boolean): () -> String {   // 함수를 받고, 함수를 돌려줌

fun main() {

    println(result())

한 줄 요약화면은 액티비티, 화면에 올리는 부품은 뷰. 뷰 바인딩을 켜면 findViewById 없이 binding.버튼이름 으로 바로 쓴다.

방법 ① 코드로 만들기

08사용자 이벤트 처리하기

한 줄 요약터치는 onTouchEvent, 키는 onKeyDown. 버튼 클릭 같은 뷰 이벤트는 “소스 + 리스너 + 등록 함수”로 처리하고, SAM 덕분에 람다로 짧게 쓴다.

class MainActivity : AppCompatActivity() {
    override fun onTouchEvent(event: MotionEvent?): Boolean {   // 액티비티의 콜백 함수 재정의
        when (event?.action) {
            MotionEvent.ACTION_DOWN -> Log.d("kkang", "Touch down event")
            MotionEvent.ACTION_UP -> Log.d("kkang", "Touch up event")
        }
        return super.onTouchEvent(event)
    }
}

매개변수 MotionEvent 객체에 이벤트 종류(action)와 좌표가 담겨 있음.

override fun onKeyDown(keyCode: Int, event: KeyEvent?): Boolean {
    when (keyCode) {
        KeyEvent.KEYCODE_0 -> Log.d("kkang", "0 키를 눌렀네요")
        KeyEvent.KEYCODE_A -> Log.d("kkang", "A 키를 눌렀네요")
        KeyEvent.KEYCODE_VOLUME_UP -> Log.d("kkang", "Volume Up 키를 눌렀네요")
        KeyEvent.KEYCODE_VOLUME_DOWN -> Log.d("kkang", "Volume Down 키를 눌렀네요")
    }
    return super.onKeyDown(keyCode, event)
}
  • onKeyDown(누른 순간), onKeyUp(뗀 순간), onKeyLongPress(오래 누름)
  • 첫 번째 매개변수 keyCode로 어떤 키인지 구분

뷰 이벤트의 처리 구조

집 초인종(이벤트 소스)을 누르면, 미리 연결해 둔(리스너 등록 함수) 집주인(이벤트 리스너)이 나와서 문을 열어요(콜백 함수 = 이벤트 핸들러). 체크박스 = 초인종, setOnCheckedChangeListener = 연결선, 리스너 객체 = 집주인, onCheckedChanged() = 문 열기.

binding.checkbox.setOnCheckedChangeListener(object: CompoundButton.OnCheckedChangeListener {
//      ↑ 이벤트 소스   ↑ 리스너 등록 함수          ↑ 익명 클래스 선언 + 객체 생성 = 이벤트 리스너
    override fun onCheckedChanged(p0: CompoundButton?, p1: Boolean) {   // 콜백 함수(이벤트 핸들러)
        Log.d("kkang", "체크박스 클릭")
    }
})

자동 생성된 TODO("Not yet implemented")는 실행하면 오류이므로 지우기. 구현할 함수 자동 생성: object에 커서 → Alt+Enter, 또는 { } 안에서 Ctrl+I.

리스너 만드는 4가지 방법 (결과는 모두 “체크박스 클릭”)

// 방법 2: 액티비티가 직접 리스너 인터페이스를 구현
class MainActivity : AppCompatActivity(), CompoundButton.OnCheckedChangeListener {
    override fun onCreate(savedInstanceState: Bundle?) {
        ...
        binding.checkbox.setOnCheckedChangeListener(this)   // 나 자신이 리스너
    }
    override fun onCheckedChanged(p0: CompoundButton?, p1: Boolean) {
        Log.d("kkang", "체크박스 클릭")
    }
}

// 방법 3: 이벤트 핸들러를 별도 클래스로
class MyEventHandler : CompoundButton.OnCheckedChangeListener {
    override fun onCheckedChanged(p0: CompoundButton?, p1: Boolean) {
        Log.d("kkang", "체크박스 클릭")
    }
}
binding.checkbox.setOnCheckedChangeListener(MyEventHandler())

// 방법 4: SAM
binding.checkbox.setOnCheckedChangeListener { compoundButton, b ->
    Log.d("kkang", "체크박스 클릭")
}

SAM ★ 교수님 강조

리스너를 등록할 때마다 object : View.OnClickListener { override fun onClick(p0: View?) { … } }를 쓰면 정말 할 말은 { … } 안의 한 줄뿐인데 껍데기가 너무 길어요. 인터페이스에 함수가 딱 하나면 “어떤 함수를 구현하는지” 헷갈릴 일이 없으니, 코틀린이 람다 하나만 주면 알아서 그 함수로 끼워 넣어 줘요. 이게 SAM입니다.

SAM = Single Abstraction Method (추상 함수가 하나) – 자바 API를 코틀린에서 람다 표현식으로 쉽게 쓰게 해 주는 기법.

조건 3가지 (빈칸 1순위!)

조건OnClickListener의 경우
①추상 함수가 하나인 인터페이스onClick() 하나뿐 ✔
②그 인터페이스가 자바로 작성안드로이드 SDK(자바) ✔
③등록하는 세터 함수도 자바로 작성setOnClickListener()도 자바 ✔

→ 그래서 binding.btn.setOnClickListener { … }가 가능.

강의 예제: 직접 만든 자바 인터페이스로 SAM

// SAM 미사용
fun samTest1() {
    val obj = SAMTest()
    obj.setInterface1(object : JavaInterface1 {
        override fun callback() { println("hello kotlin") }
    })
    obj.callback.callback()
}
// SAM 사용
fun samTest2() {
    val obj = SAMTest()
    obj.setInterface1 { println("hello SAM") }
    obj.callback.callback()
}
samTest1() → hello kotlin samTest2() → hello SAM

람다로 바꿀 때 주의할 것

리스너추상 함수람다 작성법
OnClickListeneronClick(v: View!): Unit{ Log.d(...) } – 매개변수 1개라 it = 클릭된 뷰
OnLongClickListeneronLongClick(v: View!): Boolean마지막 줄에 true
OnCheckedChangeListeneronCheckedChanged(CompoundButton, Boolean)매개변수 2개 → { compoundButton, b -> } 이름 직접 선언
binding.button.setOnClickListener {
    Log.d("kkang", "클릭 이벤트")
}
binding.button.setOnLongClickListener {
    Log.d("kkang", "롱클릭 이벤트")
    true             // ✔ 마지막 줄 = 반환값
    // return true   ✘ 람다에서는 return 사용 안 함
}
binding.checkbox.setOnCheckedChangeListener { compoundButton, b ->
    Log.d("kkang", "체크 상태: $b")   // b = 체크됐으면 true
}

참고(범위 밖): 코틀린으로 만든 일반 interface는 SAM이 안 되고 fun interface로 선언해야 해요. 그래서 조건에 “자바로 작성된”이 들어가요.
